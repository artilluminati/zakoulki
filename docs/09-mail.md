# Почта: настройка отправки писем

Письма нужны в трёх местах:

- **восстановление пароля** — пользователь сам просит ссылку;
- **уведомления** — ответили в вашем обсуждении или упомянули вас;
- **благодарность за поддержку** — после успешной оплаты доната.

Пока почта не настроена, сайт работает как обычно, просто письма не уходят (в лог пишется,
что отправка пропущена). Восстановление пароля при этом тоже недоступно — ссылки нет.

## 1. Ящик на Яндексе

1. Заведи отдельный ящик, например `zakoulki@yandex.ru` (не личный — на него будут приходить
   ссылки восстановления и письма о заказах поддержки).
2. Яндекс не принимает обычный пароль от почтовых программ. Нужен **пароль приложения**:
   [passport.yandex.ru](https://passport.yandex.ru) → «Другие устройства» → «Добавить пароль приложения» →
   придумай название («Закоулки») → Яндекс покажет пароль один раз, его надо сохранить.
   Если сервис Яндекса включён, может понадобиться подтверждение по SMS.

## 2. Переменные окружения

В `backend/.env` (на сервере — `/opt/zakoulki/backend/.env`):

```env
MAIL_ENABLED=true
MAIL_HOST=smtp.yandex.ru
MAIL_PORT=587
MAIL_USER=zakoulki@yandex.ru
MAIL_PASSWORD=пароль-приложения
MAIL_USE_TLS=true
MAIL_FROM_NAME=Закоулки
```

`MAIL_FROM` можно не задавать — тогда отправитель равен `MAIL_USER`.

Перезапусти бэкенд, чтобы настройки применились:

```bash
sudo systemctl restart zakoulki-backend
```

## 3. Проверка, что всё работает

Из папки `backend`:

```bash
venv/bin/python - <<'PY'
import asyncio
from app.services.mailer import send_email

print(asyncio.run(send_email("твой@email.ru", "Проверка «Закоулков»", "<h2>Письма работают</h2>")))
PY
```

`True` — письмо ушло. `False` — смотри лог: `journalctl -u zakoulki-backend -n 50`.

На сайте: `curl -s http://127.0.0.1:8000/health` → в поле `mail` должно быть `"on"`.

## 4. Как письма связаны с пользователем

- Письмо о **упоминании** и об **ответе** уходят тому, кто зарегистрирован на этот адрес,
  если у него включены письма об уведомлениях.
- Переключатель «Присылать письма об уведомлениях» — в профиле (`/profile`).
  Выключен по умолчанию у новых пользователей? Нет — по умолчанию включён, выключается вручную.
- Проверка ссылки восстановления: `/forgot-password` → письмо → `/reset-password?token=...` →
  новый пароль → вход с новым паролем. Ссылка действует 1 час и одноразовая.

## 5. Если письма не приходят

| Симптом | Причина | Что делать |
|---|---|---|
| `SMTPAuthenticationError` | неверный пароль приложения | создай новый пароль приложения, проверь что нет лишних пробелов |
| `SMTPServerDisconnected` | Яндекс отверг подключение | проверь `MAIL_PORT=587` и `MAIL_USE_TLS=true` (587 = STARTTLS, 465 = SSL) |
| `Connection unexpectedly closed: timed out` / нет баннера при подключении к 25/465/587 | провайдер или сеть блокирует исходящий SMTP (частое дело в домашних и офисных сетях) | проверить на другой сети или на VPS; на заблокированной сети письма не уйдут ни с каким паролем |
| письма нет, в логе «почта выключена» | `MAIL_ENABLED=false` | поставь `true` и перезапусти |
| письмо есть в спаме | фильтр Яндекса | добавь адрес отправителя в контакты |
| ссылка восстановления не открывается | в `SITE_URL` старый адрес | проверь `SITE_URL` — именно он подставляется в письма |

## 6. Демо-почта на стенде (Mailpit + клиент)

На домашнем/офисном стенде провайдер часто блокирует исходящий SMTP (см. таблицу выше).
Чтобы показывать письма без интернета, подняты три сервиса:

| Сервис | Что делает | Адрес |
|---|---|---|
| `zakoulki-mailpit.service` | принимает письма (SMTP) и хранит их | `127.0.0.1:1025` (SMTP), `127.0.0.1:8025` (веб-интерфейс, только локально) |
| `zakoulki-mailbox.service` | клиент: вход по логину и паролю сайта, показывает письма только на свой email | `127.0.0.1:8090` |
| `zakoulki-mail-tunnel.service` | публичный адрес клиента через serveo | `https://zakoulki-mail.serveousercontent.com` |

Код клиента — `backend/app/mailbox.py`. Он читает письма из Mailpit по API и отдаёт
только те, что адресованы email вошедшего пользователя; чужое письмо по ID не откроется (403).
Сам Mailpit наружу не выставлен — иначе любой желающий прочитал бы всю почту.

Настройки стенда в `backend/.env`:

```env
MAIL_ENABLED=true
MAIL_HOST=127.0.0.1
MAIL_PORT=1025
MAIL_USE_TLS=false
MAIL_USER=
MAIL_PASSWORD=
MAIL_FROM=zakoulki@zakoulki.local
MAIL_FROM_NAME=Закоулки
```

Боевые настройки Яндекса лежат рядом закомментированными — на VPS достаточно вернуть их
(и убрать `MAIL_FROM`, чтобы отправителем стал `MAIL_USER`).

Проверка:

```bash
systemctl --user status zakoulki-mailpit.service zakoulki-mailbox.service zakoulki-mail-tunnel.service
curl -s http://127.0.0.1:8000/health            # "mail":"on"
curl -s http://127.0.0.1:8025/api/v1/messages   # письма в Mailpit
```

Отправить тестовое письмо на `test@test.ru` — и открыть клиент, войдя как `tester` / `test1234`:

```bash
cd backend && venv/bin/python - <<'PY'
import asyncio
from app.services.mailer import send_email
print(asyncio.run(send_email("test@test.ru", "Проверка демо-почты", "<p>Письмо через Mailpit</p>")))
PY
```

Ограничения демо-режима:

- письма **не уходят в интернет** — только в локальный Mailpit (последние 300 штук);
- сессии клиента живут в памяти процесса: после рестарта нужно войти заново;
- пароли и ссылки из писем рабочие, но адрес в ссылке — публичный адрес сайта (`SITE_URL`).

## 7. Куда уходят письма сейчас (без SMTP)

Если `MAIL_ENABLED=false`, письма не отправляются, но система их **считает**:
в лог пишется «почта выключена — письмо не отправлено». Это удобно для разработки —
на боевом сервере не будет случайных писем с тестовых аккаунтов.
