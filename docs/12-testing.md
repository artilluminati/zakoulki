# Групповое тестирование

Рекомендованное требование проекта — «групповое тестирование». Ниже чек-лист,
по которому прогоняют сценарии несколько человек (оптимально 5–10).
Дата и участники фиксируются — это потом попадает в отчёт.

## Как проводим

1. Берём **боевой стенд** (не локальную копию): так проверяется всё сразу — фронт, бэк,
   почта, оплата.
2. Каждый участник проходит **свой сценарий** (таблица ниже), отмечает результат
   и описывает найденное.
3. Время на сценарий — 10–15 минут. Кто закончил раньше — берёт следующий.
4. Все находки — в таблицу: **что делали → что ожидали → что получилось → скриншот**.
5. Ошибки делятся на: **блокеры** (не работает основной сценарий), **ошибки**,
   **мелочи** (текст, вёрстка). Блокеры чиним сразу, остальное — по списку.

## Что фиксируем

| Дата | Участник | Сценарий | Итог | Комментарий / скриншот |
|---|---|---|---|---|
| | | | ОК / ошибка | |

## Готовность к «групповому тестированию» в отчёте

- список участников и их ролей (обычные пользователи, модератор, администратор);
- дата и ссылка на стенд;
- количество найденных и исправленных дефектов (например: «найдено 14, исправлено 12,
  2 отложены как несущественные»);
- вывод: что оказалось слабым местом.

## Полезно

- Тестировать с телефона: у всех разные экраны — ловятся проблемы вёрстки.
- Тестировать в «полевых» условиях (мобильный интернет) — там видна разница
  между «у меня открылось» и «у всех открывается».
- Не проверять «по памяти»: сценарий выполняется по шагам из таблицы.
