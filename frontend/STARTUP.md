# Закоулки — MVP

FastAPI backend + Next.js frontend. Карта на JavaScript API Яндекс Карт,
оформленная как рабочий стол Windows XP: плавающие окна фильтра категорий,
добавления мест, своих мест и аккаунта.

## Backend

```bash
cd backend
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env        # поправьте DATABASE_URL/SECRET_KEY при необходимости

# создаём postgres-базу заранее (например, createdb zakoulki)

alembic revision --autogenerate -m "init"
alembic upgrade head

python -m app.db.seed       # наполняет города и категории

uvicorn app.main:app --reload
```

Backend поднимется на `http://localhost:8000`, документация — `http://localhost:8000/docs`.

Хэширование паролей — через `pwdlib[argon2]` (см. `app/core/security.py`);
`passlib` больше не используется, чтобы не упираться в известную
несовместимость `passlib` со свежими версиями `bcrypt`.

## Frontend

```bash
cd frontend
npm install
cp .env.local.example .env.local
```

Впишите в `.env.local` бесплатный ключ JavaScript API Яндекс Карт
(получить: https://developer.tech.yandex.ru/ → «Подключить API» →
«JavaScript API и HTTP Геокодер»):

```
NEXT_PUBLIC_YANDEX_MAPS_API_KEY=ваш_ключ
```

```bash
npm run dev
```

Frontend — `http://localhost:3000`.

- **Главная (`/`)** — экран выбора города в духе современного логин-скрина.
- **`/map/[citySlug]`** — рабочий стол Windows XP поверх карты Яндекс:
  - окно **«Категории»** — фильтр меток, перетаскивается и растягивается,
    список со скроллом (не ломается при любом числе категорий);
  - окно **«Добавить место»** — выбор точки на карте (клик ставит временную
    метку) → название и категории места → **обязательная первая публикация**
    (описание + хотя бы одна фотография) → место появляется на карте только
    после того, как всё это опубликовано;
  - окно **«Мои места»** — список мест, которые добавили вы, с инлайн-
    редактированием названия/категорий и удалением (с подтверждением);
  - окно **«Аккаунт»** — вход/регистрация или профиль с кнопкой «Выйти».

### Как устроено добавление места (окно «Добавить место»)

Раньше можно было создать место без единой фотографии. Теперь форма требует
три шага подряд, прежде чем место попадёт на карту:

1. `POST /api/places` — создаётся само место (название, координаты, категории).
2. `POST /api/posts` — создаётся первая публикация (текст описания) для этого места.
3. `POST /api/photos` (multipart, может повторяться) — загружается минимум одна
   фотография для этой публикации.

Кнопка отправки формы заблокирована текстом на выбор точки/фото, пока не
выбраны точка на карте, название, текст описания и хотя бы один файл. Пока
идёт цепочка запросов, кнопка показывает стадию: «Создаём место…» →
«Публикуем описание…» → «Загружаем фото…».

### Как устроено «Мои места» (редактирование и удаление)

- Список строится на клиенте фильтрацией уже загруженных мест города по
  `place.created_by === user.id` — отдельный API-запрос не нужен.
- Редактирование — инлайн-форма (название + чекбоксы категорий) →
  `PATCH /api/places/{id}`. Координаты через это окно пока не меняются
  (см. «Что дальше»).
- Удаление — двухшаговое подтверждение («Удалить» → «Точно удалить?») →
  `DELETE /api/places/{id}`.
- Backend уже проверяет, что редактировать/удалять место может только его
  автор (см. `app/api/routes/places.py`), фронт на это не полагается —
  ошибку сервера тоже покажет.

### Страница места (`/place/[slug]`)

- Slug теперь всегда генерируется на латинице: `slugify()` в
  `app/api/routes/places.py` сначала транслитерирует кириллицу («Живописный
  мост» → `zhivopisnyy-most»), затем уже чистит спецсимволы. Старые места,
  созданные до этого изменения, сохранили кириллический slug — при желании
  пересоздайте их или проставьте новый slug вручную через `/docs`.
- Бэкенд получил `GET /api/places/slug/{slug}` (раньше был только поиск по
  числовому `id`, поэтому страница отдавала 404 на любой slug).
- На странице — фотогалерея из всех публикаций (клик открывает полноразмерный
  просмотр), лента публикаций с автором и датой, кнопка «+ Добавить
  публикацию» (текст + необязательные фото) для авторизованных пользователей.
- В балуне метки на карте показывается обложка — фото первой публикации
  места (`place.cover_photo`, вычисляется на бэкенде, чтобы фронту не нужно
  было делать лишний запрос на каждую метку).



- `lib/auth.tsx` — React-контекст `AuthProvider`/`useAuth()`, обёрнут вокруг
  всего приложения в `app/layout.tsx`. Хранит JWT в `localStorage`, при
  загрузке страницы проверяет токен через `GET /api/auth/me`.
- `components/desktop/AuthPanel.tsx` — форма входа/регистрации и профиль.
- `components/desktop/AddPlacePanel.tsx` и `MyPlacesPanel.tsx` — если
  пользователь не авторизован, показывают кнопку «Войти / Зарегистрироваться»,
  которая открывает окно «Аккаунт» (колбэк `onRequestLogin` из `MapDesktop`).
- `lib/api.ts` — axios-интерцептор подставляет `Authorization: Bearer <token>`
  во все запросы.
- `lib/errors.ts` — общий `getApiError()`, приводит ответ FastAPI (строка,
  объект валидации Pydantic или список объектов при 422) к читаемой строке.

### Про лимиты Яндекс Карт

Используется только базовый JavaScript API + кластеризация меток — отдельного
суточного лимита на это в Условиях использования нет (лимиты есть только у
Показа Панорам — 100/сутки, HTTP Геокодера — 1000/сутки, Static API —
100/сутки, API Геосаджест — 1000/сутки, Tiles API — 30 rps). Эти функции в
проекте не используются вовсе, поэтому выбор точки на карте их не расходует.
Скрипт карты (`lib/yandexMaps.ts`) грузится один раз за сессию браузера.

## Что уже готово

- **Backend**: модели (users, cities, categories, places, posts, photos),
  JWT-регистрация/логин/`me`, полный CRUD для places/posts/photos (с проверкой
  авторства), фильтры по городу/категории/поиску/радиусу, загрузка фото через
  Pillow, Alembic-миграции.
- **Frontend**: современная главная с выбором города; `/map/[citySlug]` —
  рабочий стол в стиле Windows XP с картой Яндекс, перетаскиваемыми/
  resizable окнами категорий, добавления места (с обязательным первым постом
  и фото), своих мест (редактирование/удаление) и аккаунта; полноценная
  авторизация через общий React-контекст.
